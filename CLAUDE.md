# FeeApp — architect's fee proposal app (first rough version, 28 Oct 2026)

Andre is a non-technical founder learning to direct Claude. Claude builds; Andre tests on his phone and reports. Explain changes in plain words. Build only what is asked.

## What it is
A phone-first web app for a South African architect to work out a professional fee while sitting with a client, show a branded proposal, and send it. Fees follow the SACAP guideline, Board Notice 885 of 2026.

## Front door and disciplines (added 28 Oct)
The app opens on a front door with six tiles, the six Council for the Built Environment professions: Architecture (SACAP, live), Engineering (ECSA), Quantity surveying (SACQSP), Project and construction management (SACPCMP), Landscape architecture (SACLAP), Property valuation (SACPVP). A tile is live when a fee module with that id has registered itself in `window.FEE_MODULES` (the list `DISCIPLINES` at the top of the script). Each proposal carries a `discipline` field and the list screen shows only the chosen discipline's proposals. To add a discipline: write `fees-<council>-<year>.js` in the same shape as `fees-2026.js` (id, discipline, council, country, notice, gazette, complexities/brackets, stages, wording), register it, add a `<script>` tag. The calculation code currently assumes the SACAP shape (cost brackets × complexity, stage split, repeat rule); a council with a different structure will need its own calc branch. Do not guess another council's rules: read its gazette (ECSA BN 783 of 2025, Gazette 52691; SACQSP BN 741 of 2025, Gazette 52152; SACPCMP BN 168 of 2019, Gazette 42697; SACLAP BN 47 of 2013, Gazette 36307; SACPVP BN 138 of 2010, Gazette 33614) and have a practising member check the result. (All six are built as of 29 Oct.)

## Multi-disciplinary tile, final shape (29 Oct, Andre's second correction)
Same project header and Value of works as every tile, then a tab strip with the disciplines (Architecture, Quantity surveying, Structural, Civil, Mechanical, Electrical). Each tab is that discipline's own section (Fee basis, Work stages, Repeated designs where relevant) with an Include tick. Architecture and QS are priced on the project's value of works; each engineering tab asks for the value of ITS OWN works (structural works, electrical installation…) because that is what the ECSA tables are read on. Pricing every engineering discipline on the whole building was the error that produced a R219m fee on a R450m project. The live total shows the fee as a % of the value of works as a sanity check (all consultants on guideline rates come to well above Andre's rule of thumb of 12 to 14%, because the gazette tables themselves are high at that scale: SACAP alone ≈ 10% at R450m; practitioners discount). `MULTI_DISC` lists the tabs; a multi proposal's lines carry `key` and `on`. **Several items per engineering tab (29 Oct, Andre's request):** an engineering tab (one with `own`) can hold more than one line with the same `key`: "+ Add another … item" inserts a new line after the last line of that tab (Include ticked, the tab's default table, own value), each item has an optional description (`l.label`, e.g. "Access roads") and a Remove link (not on the first item), and `lineTitle()` numbers unlabelled items ("Civil engineering 2"). The tab button shows a count when more than one item is included. Architecture and QS stay single. This is how civil on Table 1 (roads) and civil on Table 3 (building civils) go on one proposal. Checked: R8m Table 3 (R1 073 500) + R24m Table 1 (R2 758 500) = R3 832 000, proposal and PDF list both.

## Single tiles stay simple; Multi-disciplinary is its own tile (29 Oct, Andre's correction)
Andre did not want the Architecture / QS / Engineering screens changed. So: the single-discipline tiles show the ORIGINAL screens (How is this job charged? · Value of works · Fee basis · Work stages · Repeated designs · Hourly work · Disbursements · Adjustments) and the original proposal/PDF layout. Under the hood a single-discipline proposal is one `table` line plus, when "Value + hours" or "Hours only" is chosen (`p.chargeMode`), one `hours` line; `ensureClassicLines()` keeps it to at most one of each. A seventh front-door tile, **Multi-disciplinary engineering** (`discipline: "multi"`, module ECSA), is the only place with the "lines" screen: add structural, civil, mechanical, electrical, management lines (one ECSA table each, on the project's value or its own portion) plus hours; the proposal numbers the disciplines. The `percent` and `lump` line types exist in the engine but are not offered anywhere yet.

## Fee lines engine (29 Oct)
A proposal is a list of **fee lines** (`p.lines`). Each line has a `type`:
- `table`: a council's fee table (`discipline` = module id, `sel`, `stages`, `stageKey`, `repeatPct`). Priced on the project's value of works (`valueMode: "project"`, repeated-units adjustment applies) or on the line's own value (`valueMode: "own"`, `ownBasis` area × rate or value; no repeat adjustment). This is how an electrical subcontract of R8m sits inside a R100m building, and how structural + civil + electrical engineering go on one proposal.
- `percent`: a negotiated percentage of the value (project's or own). Typical for interior design, which has no statutory council or gazetted scale.
- `lump`: a negotiated lump sum with a description.
- `hours`: time-based rows at a module's guideline rates or own rates.
Project level: value of works (single / scheme), disbursements, discount (on all lines), notes, invoices. `calc()` returns `lines[]` (one result per line) plus totals. The proposal and PDF number the lines and show a "Fees by discipline and service" section when there is more than one; invoice planning makes one draft per stage of each table line and one per other line. Old single-discipline proposals migrate to one table line plus, if they had hours, one hours line. The front door still picks the practice's own discipline: it sets the default for new proposals and which list a proposal appears in (`p.discipline`).

## Engineering (ECSA) and Quantity surveying (SACQSP) modules (added 28 Oct)
`fees-ecsa-2025.js` (Board Notice 783 of 2025, Gazette 52691) and `fees-sacqsp-2024.js` (Board Notice 741 of 2025, Gazette 52152; hourly rates Board Notice 778 of 2025). Both gazettes were read from the PDFs; the SACQSP basic fee table and stage table are images in the gazette and were read from rendered page images, then checked (each primary charge = previous primary + previous marginal rate over the bracket). All three gazette worked examples reproduce exactly: ECSA A (rural road R24m, Table 1 × 0.85 = R2 344 725), ECSA C (electrical building R8m, Table 8 = R1 284 000), SACQSP (building, BoQ, R77,5m = R6 349 750).

**Generic module interface** (index.html no longer knows about "complexity"): `selectors` (seg / select / multi / number; options may be a function of the current selection), `resolve(sel)` → `{brackets, factor, stageKey, stages, summary[], hint, factorLabel}`, `feeLabel`, `repeatedBuildings {stages14Percent, stageIds, note}`, `partialServicePoints` (ECSA +10 points when not all stages are provided), `belowTableNote` (ECSA tables start at R1 050 001), `hourlyRates` (may be empty → own rate) + `hourlyNote`, `disbursementNote`, `disbursementAttendancePercent`. Bracket rows are `[lo, hi|null, primary, %, base]`; the secondary fee is % of (value − base); base defaults to lo (SACAP). A proposal stores `sel` and `stageKey`; stages are regenerated when the resolved stageKey changes, otherwise the user's stage edits are kept.

**ECSA factor lists are per table (29 Oct, Andre spotted it):** each factor carries the tables it belongs to (gazette Tables 2A, 3A, 4A, 5A, 6A, 7A, 8A, 11A) and the tick list changes with the Discipline dropdown; a factor ticked under one table is ignored once another table is chosen. The questions for practitioners are in `QUESTIONS-FOR-ENGINEER-AND-QS.md`.

**Judgement calls to confirm with an engineer / QS:** ECSA factors are multiplied together as the gazette says, with range factors at their lower value; ECSA Table 2 (RC/steel additional design fee), lead consultant +10% and principal agent +1% are not built. SACQSP replication uses the chosen contract's stage split rather than the separate "Replication of prototype" row; multiple procurement contracts use the override row with stage 4 = 15 + 20.

## Project and construction management (SACPCMP) module (added 29 Oct)
`fees-sacpcmp-2019.js`: **Board Notice 168 of 2019, Gazette 42697, 13 September 2019** (`201909/42697bn168.pdf` on gov.za), read from the PDF text. This is the LAST gazetted SACPCMP tariff: a rebased 2022 tariff went out for comment as Board Notice 182 of 2021 (Gazette 45649) but its gazetting was suspended after engagement with Public Works and the Competition Commission, and Board Notice 392 of 2023 (Gazette 48017) is a fee policy with no figures. The council's later gazettes (e.g. Board Notice 867 of 2025) are registration fees. So the 2019 figures are the current guideline and a PrCPM will probably escalate them by agreement; the proposal's closing note says so.
**Method (clause 7):** one table for construction project management on building projects, primary fee + "add %" of the cost over the bracket's "for value over" figure: the same shape as SACAP/ECSA, no new calc branch. Stages per clause 8: 10 / 10 / 25 / 10 / 40 / 5. Selector: new works, or alterations and additions at +25% (clause 12, applied as a factor). No Rand hourly rates in the gazette (clause 10.3 points to the Department of Public Works consultant rates), so the hourly list is empty. Disbursements at cost (clause 11). No gazette worked example; hand checks: R5m new = 334 400 + 1 000 000 x 7,85% = R412 900; R45m alterations = (2 392 340 + 13 000 000 x 6,30%) x 1,25 = R4 014 175 (reproduced in the app).
**Table oddities kept as printed:** bracket 2 ends at 176 650 but bracket 3 starts at 175 400; bracket 7's primary is 2 392 340 where bracket 6 ends at 2 392 400; bracket 9's primary is 7 992 400 where bracket 8 ends at 7 992 340 (the last two look like transposed digits in the gazette).
**Judgement calls:** repeat card left at 100% (the tariff has no repeated-building rule; clause 6.6 separate sites/phases is not built); clause 5.2 termination surcharge and clause 4 supplementary services not built.
Check (Python): `pc=[(1,1e6,16650,8,0),(1000001,2e6,96650,8,1e6),(2000001,4e6,175400,7.95,2e6),(4000001,8e6,334400,7.85,4e6),(8000001,16e6,648400,7.8,8e6),(16000001,32e6,1272400,7,16e6),(32000001,64e6,2392340,6.3,32e6)]; f=lambda v:[b[2]+(v-b[4])*b[3]/100 for b in pc if b[0]<=v<=b[1]][0]; print(f(5e6), f(45e6)*1.25)` gives 412900.0 4014175.0

## Landscape architecture (SACLAP) module (added 29 Oct)
`fees-saclap-2013.js`: **Board Notice 47 of 2013, Gazette 36307, 5 April 2013** (`201409/36307bn47.pdf` on gov.za), effective 1 January 2013, plus the SACLAP Code of Practice and Fees Protocol (January 2011, saclap.org.za) for the stage split and rules. This is the last gazetted SACLAP guideline fee notice that could be found, and the only one SACLAP lists under Professional Practice; the council's later gazettes (Board Notices 44 of 2017, 57 of 2018, the 2022 and 2024 rates tables) are registration fees under section 12(1). The 2013 figures are therefore the current guideline; the closing note says rates may be escalated by agreement.
**The method does not fit the bracket shape exactly.** The gazette gives a "Scale of Fees" as a PERCENTAGE OF PROJECT VALUE at 17 points (R400 000 = 14,00% ... R9 000 000 = 9,90%), says projects under R400 000 are "based on published hourly rates", and gives nothing for values between the points or above R9m. **Closest honest fit (judgement call):** the fee at each gazetted point is exactly value x gazetted %; between two points the fee is interpolated in a straight line; above R9m the 9,90% is held flat. That is exactly what a bracket row expresses, so the module DERIVES its bracket rows from the scale (`[point, next - 1, point x %, marginal %, point]`) and index.html needs no new branch. The proposal therefore shows "primary fee + marginal %" like the other councils; the summary line explains it is a sliding percentage. Below R400 000 the module reports "below the table" and points to Hours only / Lump sum. Interpolating the percentage instead of the fee would differ by about 0,2% (R3m: R307 200 vs R307 843).
**Also from the protocol:** stages 5 / 15 / 15 / 30 / 32 / 3 (clause 10.5); partial service = stages performed + 10% of the applicable fee (clause 8), built as a selector that applies a 1,10 factor (untick the stages not performed); +1% principal agent and +1% principal consultant, master plans at 1% (clause 7.1), alterations premium of 15% on the affected stage (10.9), contract administration only at 35% + 15% (10.9) are NOT built. Hourly rates from the 2013 notice (R1 440 / 1 050 / 790 / 530 / 260). Repeat card at 100%.
Hand checks (reproduced in the app): R2 000 000 = 2 000 000 x 10,99% = R219 800 (a gazetted point); R3 000 000 = 290 920 + 200 000 x 8,14% = R307 200; R12 000 000 = 891 000 + 3 000 000 x 9,90% = R1 188 000 = 12m x 9,90%.
Check (Python): `sc=[(400000,14),(500000,13.53),(600000,13.16),(700000,12.86),(800000,12.62),(900000,12.42),(1e6,12.25),(1.2e6,11.95),(1.4e6,11.7),(1.6e6,11.45),(1.8e6,11.21),(2e6,10.99),(2.4e6,10.64),(2.8e6,10.39),(3.5e6,9.94),(5e6,9.92),(9e6,9.9)]` then for a value v find the last point a at or below v and the next point b; fee = a.value x a.% + (v - a.value) x (b.value x b.% - a.value x a.%) / (b.value - a.value), or v x 9,90% from R9m. Gives 219800, 307200, 1188000.

## Property valuation (SACPVP) module (added 29 Oct)
`fees-sacpvp-2010.js`: **Board Notice 138 of 2010, Gazette 33614, 15 October 2010** (`201409/33614138.pdf` on gov.za), effective 1 October 2010; the text matches the copies on sacpvp.co.za and saiv.org.za. It is the only gazetted SACPVP guideline professional fee notice that could be found; the council's annual gazettes (e.g. Notice 7467 of 2026, Gazette 54677) are registration fees under section 12(1). Sixteen-year-old figures: the closing note says rates may be escalated by agreement.
**The method is a per-valuation tariff, not a construction fee.** Clause 1.1 is an ad valorem tariff on the VALUE OF THE PROPERTY: basic tariff for the bracket plus "R x per R1 000 over" the bracket's lower figure. R15 per R1 000 = 1,5%, so the table converts exactly to bracket rows (checked: each basic tariff = previous basic + previous rate over the whole bracket) and no new calc branch is needed. In the app the "Value of works" field IS the property value (the module's cost-of-works note says so on the input screen and the proposal); there is one stage, "Valuation and report", at 100%. Selectors: tariff = valuation on property value, or rental valuation on gross annual rental (clause 3.0: 27% up to R15 000, then 4 050 + 3%, then 5 100 + 0,75%; the R1 600 minimum is a note, not enforced); adjustments = a second value for the same property +30% (clause 1.2) and revaluation within 12 months -50% (clause 1.5), applied as factors and multiplied if both are ticked. Hourly rates from clause 2.1 (R1 600 ... R450). Disbursements per clauses 6 and 7 (R4,50 per km etc.).
**Not built:** prescribed forms +25% capped at R250 (1.3), sectional title investigation time (1.6), before-and-after (1.7), part of a property (1.8), time charge not less than the ad valorem fee (2.2), court/arbitration at 1,5 x hourly and R12 000 per day (4, 5). Use Hours or a Negotiated line.
Hand checks (reproduced in the app): R2 500 000 = 7 700 + 1 500 000 x 0,15% = R9 950; with a second value x 1,30 = R12 935; R30 000 000 = 38 700 + 5 000 000 x 0,07% = R42 200; rental, GAR R240 000 = 5 100 + 190 000 x 0,75% = R6 525.
Check (Python): `av=[(1,5e4,500,0,0),(50001,15e4,500,1.5,5e4),(150001,35e4,2000,1,15e4),(350001,5e5,4000,.8,35e4),(500001,75e4,5200,.6,5e5),(750001,1e6,6700,.4,75e4),(1000001,5e6,7700,.15,1e6),(5000001,1e7,13700,.14,5e6),(10000001,2.5e7,20700,.12,1e7),(25000001,5e7,38700,.07,2.5e7)]; f=lambda v:[b[2]+(v-b[4])*b[3]/100 for b in av if b[0]<=v<=b[1]][0]; print(f(2.5e6), f(2.5e6)*1.3, f(3e7))` gives 9950.0 12935.0 42200.0

## How the fee is calculated (gazette page 3)
fee = primary fee for the bracket + (value of works − bracket "from") × secondary %.
Gazette check: R3 000 000 low complexity = 246 281,11 + 999 999 × 10,40% = R350 281,00.
Then: × percentage of stages included (default 2/15/20/10/20/30/3) − discount, + VAT if registered.

## Repeated buildings (added 28 Oct, Andre's request; mixed complexes added the same day)
Gazette clause 23. Value of works has two forks (Andre's design, 28 Oct): **Single project** (one project priced as a whole; a house with outbuildings is a single project; basis = area × rate OR a value) and **Development scheme** (several buildings on one site under one contract), which has two headed lists: **Primary buildings** (bespoke once-off buildings, each with area × rate OR value, full fee) and **Repeated units** (one row per unit type: name, quantity, then size × rate of ONE unit or value of one unit; the row's first unit is the prototype at full fee, the rest get the repeat rate). Data: both lists live in `p.blds`, with `rep: true` marking a unit-type row; `protos` is kept at 1 (one design per row; a second design is a second row). The Repeated designs card (the % for stages 1 to 4 on each repeat, default 35, editable "by agreement") shows only in the scheme fork. Stages 5 and 6 always at full fee. Old proposals (modes area/direct/multi, repeat.on/units) are migrated on load by `migrate()`.
**Judgement call (tell Andre if it should change):** the guideline fee is worked out on the TOTAL value of works (all buildings), then the stages 1 to 4 portion is scaled by a value-weighted factor: Σ(building value × its factor) ÷ total value, where a bespoke building's factor is 1 and a repeated row's factor is (prototypes + repeats × 35%) ÷ quantity. Working on the total value uses the sliding scale correctly for the size of the project. The alternative, a fee per building and summed, would give a higher fee because smaller values attract a higher percentage. Worked check (28 Oct): clubhouse 600 m² × R18 000 + gym 300 m² × R15 000 + 15 × unit 120 m² × R15 000 = R42,3m medium; factor 0,6128; fee R3 544 510.

## Hourly work (added 28 Oct, Andre's request)
"How is this job charged?" at the top of the inputs: **On value of works** (default), **Value + hours** (cost-based fee plus time-based additional services, gazette clause 18), **Hours only** (whole job time-based; value, complexity, stages and repeat cards are hidden). Lines: role from gazette Table 4 (Method 2 guideline rate prefilled, editable) or "Other (own rate)", rate, hours, description. Stored in `p.time = { mode, lines }`. The discount applies to the professional fee (cost-based part plus hours), not to disbursements. VAT on fee plus disbursements.

## Disbursements (added 28 Oct, Andre's request)
Gazette clause 35 and the reimbursement table. Each line: a category from the gazette's list (in fees-2026.js), optional detail, cost, and an attendance percentage (default 10, set to 0 for cost only). Disbursements are shown as an estimate, excluded from the professional fee, added to the total, and attract VAT if the firm is registered.

## Delete
Delete asks inside the page (Yes, delete / Keep it). It does not use the browser's confirm() pop-up because some browsers, including the Claude preview pane, block pop-ups and the delete silently did nothing.

## Screens
Home (list of proposals) → New/Edit (inputs, live fee at the top) → Proposal (branded document; Share, Save as PDF, Edit) · Settings (firm name, tagline, contact, logo, accent colour, default rate per m², VAT, validity days).

## Storage
Everything is in the phone's browser storage (localStorage): proposals and settings, logo as a data URL. Nothing is sent anywhere. Clearing browser data wipes it. A backend comes later if needed.

## Sharing
"Share / send" uses the phone's share sheet (WhatsApp, email, etc.) with a text summary; on a desktop browser it falls back to an email draft. "Save as PDF" uses the browser's print dialog; print CSS hides everything except the proposal.

## Invoices and payments (added 28 Oct)
Button on the inputs screen → invoice screen per proposal. Summary: proposed fee (incl. VAT and disbursements, i.e. `calc().total`), invoiced, paid, outstanding (invoiced − paid), still to invoice. Invoice rows: number, date, description, amount (as on the invoice, incl. VAT when registered), Paid tick with received date and amount (part payments show "short"). "Plan invoices from the work stages" adds one draft line per included stage (stage amount × discount × VAT), plus hourly work and disbursements lines. Stored in `p.invoices`. The home list shows "R… outstanding" per proposal. Not built: reading an invoicing folder from the PC (a desktop job), a statement PDF.

## Invoice documents (added 28 Oct)
Settings → Invoicing: VAT registration number, invoice prefix + next number (auto-numbering, zero-padded to 4), payment terms, banking details. "Add an invoice" takes the next number; planned lines get a number when first sent. Each invoice row has Send PDF / Download: `buildInvoicePdf(inv)` draws a TAX INVOICE (or INVOICE when not VAT registered) with the shared letterhead (`pdfHeader`), invoice number/date/VAT no., invoice-to block, description + amount excl. VAT (backed out of the stored incl. amount), VAT, TOTAL DUE, PAID stamp if paid, payment terms, banking details with the invoice number as reference, footer. Gazette clause 34: accounts due on presentation.

## Acceptance (added 28 Oct)
The proposal (screen and PDF) ends with an Acceptance block: "I/we accept this fee proposal and appoint <firm>…" and Name / Signature / Date lines. A click-to-accept link needs a server (the backend stage).

## PDF (added 28 Oct)
`buildPdf()` draws the proposal with jsPDF + jspdf-autotable (cdnjs, pinned versions) in the page: header with logo in proportion, firm, title, basis, fee tables, hours, disbursements, proposed fee, notes, gazette wording, page footer. "Send PDF to client" uses the share sheet with the PDF file (Android Chrome, iOS 15+); where files cannot be shared it downloads the PDF. "Download PDF" saves it. "Share as text instead" keeps the old text share. jsPDF's built-in fonts are Latin-1 only: no Unicode minus or ellipsis in PDF strings.
